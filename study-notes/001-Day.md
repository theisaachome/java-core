1. String
   In Java, a String is an object that represents a sequence of characters. Unlike many other languages where strings are treated as character arrays, Java implements strings as objects of the java.lang.String class.

Immutability: Strings in Java are immutable, meaning once a String object is created, its state cannot be modified. Any operation that appears to modify a string (such as concatenation or substring extraction) actually creates and returns a brand-new String object in memory.

Syntax: Strings can be created using string literals (String s = "Hello";) or the new keyword (String s = new String("Hello");).

2. String Pool
   The String Pool (or String Intern Pool) is a special region of memory located within the Java Heap.

Memory Optimization: Because strings are immutable, Java stores literal strings in the String Pool to save memory. If two variables are assigned the exact same string literal, Java points both variables to the exact same memory address in the pool rather than creating duplicate objects.

Literals vs. new:

String s1 = "Java"; checks the String Pool. If "Java" exists, s1 points to it. If not, it creates it in the pool.

String s2 = new String("Java"); creates a new object in the general heap regardless of whether "Java" already exists in the String Pool. You can use the .intern() method to manually add a heap string to the pool.

3. StringBuilder
   StringBuilder is a mutable sequence of characters introduced in Java 5 to handle heavy string manipulation efficiently.

Mutability: Unlike String, modifying a StringBuilder object (using methods like .append(), .insert(), or .delete()) alters the original object in memory without creating new ones, drastically reducing memory overhead and garbage collection pressure.

Thread Safety: StringBuilder is not synchronized, meaning it is not thread-safe. However, because it lacks the overhead of thread synchronization, it is faster than StringBuffer and is the preferred choice for single-threaded environments.

4. StringBuffer
   StringBuffer is the older, thread-safe counterpart to StringBuilder.

Mutability: Just like StringBuilder, it represents a mutable sequence of characters.

Thread Safety: All public methods in StringBuffer are synchronized. This ensures that multiple threads can safely modify a StringBuffer instance concurrently without data corruption.

Performance: Because of the performance cost associated with synchronization, StringBuffer is slower than StringBuilder and is typically only used when thread-safe string mutation is explicitly required.

Approach 1: Using StringBuilder (Most Efficient & Idiomatic)
Java
public class StringReverser {

    public static String reverseUsingBuilder(String input) {
        if (input == null) {
            return null;
        }
        // StringBuilder provides a built-in reverse() method
        return new StringBuilder(input).reverse().toString();
    }
}
Approach 2: Manual Implementation (Using a Character Array)
Java
public class StringReverser {

    public static String reverseManual(String input) {
        if (input == null) {
            return null;
        }
        
        char[] chars = input.toCharArray();
        int left = 0;
        int right = chars.length - 1;
        
        // Swap characters from outward in
        while (left < right) {
            char temp = chars[left];
            chars[left] = chars[right];
            chars[right] = temp;
            left++;
            right--;
        }
        
        return new String(chars);
    }
}

1. Primitive vs. Reference Types
   Java is statically typed and features two distinct categories of data types: primitive types and reference types.

Primitive Types: These are the most basic data types built directly into the language. Java has 8 primitives: byte, short, int, long, float, double, boolean, and char. They store actual numerical, boolean, or character values directly in memory.

Reference Types: These include objects, arrays, and interfaces (e.g., String, LocalDate, custom classes, int[]). A reference variable does not hold the actual data object; instead, it holds a memory address (reference) pointing to where the object is allocated on the heap.

2. Stack vs. Heap Memory
   Java manages runtime memory across different areas, with the Stack and the Heap being the two most critical for variable storage.

Stack Memory:

Used for static memory allocation and the execution of threads.

Every time a method is called, a new "stack frame" is created to hold local variables (including primitives and object references).

Variables in the stack are destroyed as soon as the method finishes execution (Last-In, First-Out). Access is extremely fast.

Heap Memory:

Used for dynamic memory allocation for all objects and arrays, regardless of where they were instantiated.

When you use the new keyword, space is carved out on the heap.

Heap objects persist beyond the scope of a single method until the Garbage Collector reclaims them when no active references point to them.

3. == vs. .equals()
   Understanding the difference between equality operators is essential for bug-free code.

== (Operator):

Compares the actual value stored in the variable.

For primitives, it compares numeric/boolean values (e.g., 5 == 5 is true).

For reference types, it compares the memory addresses (i.e., whether both references point to the exact same object in the heap).

.equals() (Method):

Defined in the Object class and overridden by classes (like String, Integer, or custom classes) to compare logical equivalence (the contents or state of the objects).

## Day 1: Core Memory & Type Comparisons

### 1. Primitive vs. Reference Types

* **Primitive Types:** These are the most basic data types built directly into the language. Java has 8 primitives: `byte`, `short`, `int`, `long`, `float`, `double`, `boolean`, and `char`. They store actual numerical, boolean, or character values directly in memory.

---
