## 1. Core Concepts & Short Notes

### 1. Inheritance (`extends`)
* **Definition:** Inheritance is a mechanism where a new class (subclass/child) acquires the state (fields) and behaviors (methods) of an existing class (superclass/parent).
* **Relationship:** Represents an **"IS-A"** relationship (e.g., a `CreditCardProcessor` **IS-A** `PaymentProcessor`).
* **Key Rules & Behaviors:**
    * **Single Inheritance:** Java supports single inheritance for classes using the `extends` keyword (a class can only directly extend one parent class).
    * **Encapsulation & Access:** `private` members of the superclass are inherited but cannot be accessed directly by the child class (accessible via public/protected getters/setters or `protected` fields).
    * **Constructor Chaining:** Constructors are **not inherited**. A child constructor automatically invokes the superclass's no-arg constructor (`super()`) as its first line unless an explicit call like `super(...)` is supplied.

---

### 2. Method Overriding (`@Override`)
* **Definition:** Method overriding occurs when a child class provides a specific implementation for a method that is already defined in its parent class.
* **Key Rules & Constraints:**
    * **Exact Signature:** Method name, parameter types, and parameter order must match the parent method exactly.
    * **Covariant Return Type:** The return type must be identical to, or a subtype of, the return type declared in the parent method.
    * **Access Modifier Restrictions:** Cannot restrict visibility (e.g., if parent method is `protected`, overriding method must be `protected` or `public`).
    * **`@Override` Annotation:** Always annotate overridden methods with `@Override`. It instructs the compiler to verify overriding constraints, catching typos at compile-time.
    * **Non-Overridable Methods:** `final` methods, `static` methods, and `private` methods **cannot** be overridden.

---

* **Definition:** Dynamic Method Dispatch is the mechanism by which a call to an overridden method is resolved at **runtime** rather than at compile-time.

## 2. Real-World Example Code: Payment Gateway System

```java
import java.util.ArrayList;
import java.util.List;

// 1. Superclass (Base Entity)
class PaymentProcessor {
    private final String merchantId;

    public PaymentProcessor(String merchantId) {
        this.merchantId = merchantId;
    }

    public String getMerchantId() {
        return merchantId;
    }

    // Base process method intended to be overridden by subclasses
    public void processPayment(double amount) {
        System.out.println("Processing generic payment of $" + amount + " for Merchant: " + merchantId);
    }
}

// 2. Subclass 1: Credit Card Processing
class CreditCardProcessor extends PaymentProcessor {
    private final String cardNumber;

    public CreditCardProcessor(String merchantId, String cardNumber) {
        super(merchantId); // Explicit superclass constructor call
        this.cardNumber = maskCardNumber(cardNumber);
    }

    private String maskCardNumber(String card) {
        return "XXXX-XXXX-XXXX-" + card.substring(card.length() - 4);
    }

    @Override
    public void processPayment(double amount) {
        System.out.println("[CreditCard] Authorizing $" + amount + " on card " + cardNumber 
                + " (Merchant: " + getMerchantId() + ")");
    }
}

// 3. Subclass 2: Crypto Currency Processing
class CryptoProcessor extends PaymentProcessor {
    private final String walletAddress;

    public CryptoProcessor(String merchantId, String walletAddress) {
        super(merchantId);
        this.walletAddress = walletAddress;
    }

    @Override
    public void processPayment(double amount) {
        System.out.println("[Crypto] Transferring $" + amount + " equivalent to wallet " 
                + walletAddress + " (Merchant: " + getMerchantId() + ")");
    }
}

// 4. Subclass 3: PayPal Processing
class PayPalProcessor extends PaymentProcessor {
    private final String email;

    public PayPalProcessor(String merchantId, String email) {
        super(merchantId);
        this.email = email;
    }

    @Override
    public void processPayment(double amount) {
        System.out.println("[PayPal] Charging $" + amount + " from PayPal account: " + email);
    }
}

// 5. Main Class Demonstrating Dynamic Dispatch
public class Day8Demo {
    public static void main(String[] args) {
        // Polymorphic Collection: Superclass references holding subclass instances
        List<PaymentProcessor> checkoutQueue = new ArrayList<>();

        checkoutQueue.add(new CreditCardProcessor("MCH-101", "4111111111111234"));
        checkoutQueue.add(new CryptoProcessor("MCH-102", "0x71C...39A"));
        checkoutQueue.add(new PayPalProcessor("MCH-103", "user@example.com"));

        System.out.println("=== Executing Payments via Dynamic Dispatch ===");
        
        // Loop uses Superclass type (PaymentProcessor)
        for (PaymentProcessor processor : checkoutQueue) {
            // DYNAMIC DISPATCH AT WORK:
            // At compile-time, Java checks PaymentProcessor.processPayment()
            // At runtime, JVM invokes the overridden method on actual instance
            processor.processPayment(150.00);
        }
    }
}
