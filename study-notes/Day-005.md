## 1. Encapsulation

### Detailed Notes
**Encapsulation** is a core Object-Oriented Programming principle that binds data (fields) and the behaviors operating on that data (methods) together into a single cohesive unit (a class), while hiding internal implementation details from external direct access.

* **Data Hiding & Security:**
    * Instance fields are declared `private` to shield state from unintended direct modification.
    * Internal representation remains safe from external corruption or invalid state configurations.
* **Controlled Access & Validation:**
    * Access is provided selectively via public getter and setter methods or domain operations.
    * Setters enforce domain validation constraints (invariants), throwing exceptions or rejecting invalid inputs before updating fields.
* **Maintainability & Decoupling:**
    * Encapsulation allows internal class details to be refactored without breaking client code dependent on public interfaces.

### Code Example: Encapsulated User Account
```java
public class UserAccount {
    // Hidden internal state
    private String username;
    private int securityPin;

    public UserAccount(String username, int securityPin) {
        this.username = username;
        setSecurityPin(securityPin); // Enforces validation on object instantiation
    }

    // Controlled getter
    public String getUsername() {
        return username;
    }

    // Controlled setter with domain validation
    public void setSecurityPin(int newPin) {
        if (newPin >= 1000 && newPin <= 9999) {
            this.securityPin = newPin;
        } else {
            throw new IllegalArgumentException("PIN must be a 4-digit number (1000-9999).");
        }
    }
}
```

## 2. Access Modifiers

### Detailed Notes
Access modifiers define the scope and visibility of classes, constructors, methods, and variables across Java packages and inheritance hierarchies.

### Visibility Matrix

| Access Modifier | Class Itself | Same Package | Subclasses (Diff Package) | World (Everywhere) |
| :--- | :---: | :---: | :---: | :---: |
| **`private`** | Yes | No | No | No |
| **`default`** *(no keyword)* | Yes | Yes | No | No |
| **`protected`** | Yes | Yes | Yes | No |
| **`public`** | Yes | Yes | Yes | Yes |

### Key Takeaways
1. **`private`**: Strictly limited to the declaring class. Used for private fields and internal helper functions.
2. **`default` (Package-Private)**: No access keyword specified. Accessible by all classes inside the exact same package.
3. **`protected`**: Accessible within the same package and by child classes regardless of package location.
4. **`public`**: Fully visible from any package in the project. Used for public APIs.

### Code Example: Access Modifiers
```java
package com.example.model;

public class Employee {
    public String name;          // Accessible everywhere
    protected String department; // Accessible in same package & subclasses
    int internalId;              // Package-private (default access)
    private double salary;       // Accessible ONLY within Employee class

    public Employee(String name, String department, int internalId, double salary) {
        this.name = name;
        this.department = department;
        this.internalId = internalId;
        this.salary = salary;
    }

    // Private helper method hidden from outside callers
    private void calculateBonus() {
        System.out.println("Calculating bonus for internal salary evaluation...");
    }
}
```

## 3. Composition vs. Inheritance

### Detailed Notes
Both concepts facilitate code reuse, but establish distinctly different structural relationships:

### A. Inheritance ("IS-A" Relationship)
* Models dynamic relationships where a subclass extends a superclass (`class Dog extends Animal`).
* Supports dynamic polymorphism.
* **Cons:** Introduces tight coupling. Modifications in the parent class can break child class implementations unexpectedly.

### B. Composition ("HAS-A" Relationship)
* Models structural relationships where a class holds references to instances of other classes (`class Car` HAS-A `Engine`).
* Enables dynamic component swapping at runtime and simplifies unit testing via mock injection.
* **Design Principle:** *"Favor composition over inheritance"* to maintain loose coupling and protect encapsulation boundaries.

### Code Examples

#### Inheritance ("IS-A")
```java
class Vehicle {
    public void startEngine() {
        System.out.println("Engine started.");
    }
}

// ElectricCar IS-A Vehicle
class ElectricCar extends Vehicle {
    @Override
    public void startEngine() {
        System.out.println("Silent electric motor initialized.");
    }
}
```

#### Composition ("HAS-A")
```java
class Engine {
    public void start() {
        System.out.println("Engine running...");
    }
}

// Car HAS-AN Engine (Composition)
public class Car {
    private final Engine engine;

    public Car(Engine engine) {
        this.engine = engine;
    }

    public void startCar() {
        // Delegates behavior to the Engine instance
        engine.start(); 
    }
}
```

## 4. Practice Exercises & Solutions

### Exercise 1: Encapsulation & Access Boundaries

#### Requirements
Design a `BankAccount` class inside package `com.bank.account`:
1. **Fields:** `accountNumber` (String, package-private), `pinCode` (int, private), and `balance` (double, private).
2. **Constructor:** Accepts `accountNumber`, `pinCode`, and initial `balance`. Enforces that `pinCode` must be a 4-digit positive integer (1000–9999). Throws `IllegalArgumentException` if invalid.
3. **Methods:**
    * `verifyPin(int inputPin)`: Package-private helper returning `boolean`.
    * `withdraw(double amount, int inputPin)`: Public method verifying PIN and available balance before deducting funds. Returns `boolean`.

#### Solution
```java
package com.bank.account;

public class BankAccount {
    String accountNumber; // Package-private (default access)
    private int pinCode;
    private double balance;

    public BankAccount(String accountNumber, int pinCode, double initialBalance) {
        this.accountNumber = accountNumber;
        setPinCode(pinCode);
        this.balance = Math.max(0, initialBalance);
    }

    // Encapsulated setter with validation logic
    private void setPinCode(int pinCode) {
        if (pinCode < 1000 || pinCode > 9999) {
            throw new IllegalArgumentException("PIN code must be a 4-digit number.");
        }
        this.pinCode = pinCode;
    }

    // Package-private method: internal package verification helper
    boolean verifyPin(int inputPin) {
        return this.pinCode == inputPin;
    }

    // Public API with controlled access logic
    public boolean withdraw(double amount, int inputPin) {
        if (!verifyPin(inputPin)) {
            System.out.println("Transaction Failed: Invalid PIN.");
            return false;
        }
        if (amount > balance) {
            System.out.println("Transaction Failed: Insufficient funds.");
            return false;
        }
        balance -= amount;
        return true;
    }

    public double getBalance() {
        return balance;
    }
}
```

### Exercise 2: Inheritance ("IS-A") Relationship

#### Requirements
Implement an inheritance hierarchy for a notification system:
1. Create a base class `Notification` with a protected field `recipient` (String) and a public method `send(String message)`.
2. Create two child classes:
    * `EmailNotification`: Overrides `send(String message)` to print `"Sending Email to [recipient]: [message]"`.
    * `SMSNotification`: Overrides `send(String message)` to truncate `message` to 20 characters maximum if needed, then print `"Sending SMS to [recipient]: [truncated message]"`.

#### Solution
```java
public class Notification {
    protected String recipient;

    public Notification(String recipient) {
        this.recipient = recipient;
    }

    public void send(String message) {
        System.out.println("Sending default notification to " + recipient + ": " + message);
    }
}

class EmailNotification extends Notification {
    public EmailNotification(String recipient) {
        super(recipient);
    }

    @Override
    public void send(String message) {
        System.out.println("Sending Email to " + recipient + ": " + message);
    }
}

class SMSNotification extends Notification {
    public SMSNotification(String recipient) {
        super(recipient);
    }

    @Override
    public void send(String message) {
        String truncated = message.length() > 20 ? message.substring(0, 20) + "..." : message;
        System.out.println("Sending SMS to " + recipient + ": " + truncated);
    }
}
```

### Exercise 3: Composition ("HAS-A") over Inheritance

#### Requirements
Design a flexible computer architecture using **Composition**:
1. Create a `Processor` class with a method `processData()`.
2. Create a `Storage` class with a method `readData()`.
3. Create a `Computer` class that HAS-A `Processor` and HAS-A `Storage` (via constructor injection).
4. Implement a `run()` method in `Computer` that triggers reading storage first, then processing data.

#### Solution
```java
class Processor {
    private final String model;

    public Processor(String model) {
        this.model = model;
    }

    public void processData() {
        System.out.println("Processing data using " + model + " CPU...");
    }
}

class Storage {
    private final int capacityGb;

    public Storage(int capacityGb) {
        this.capacityGb = capacityGb;
    }

    public void readData() {
        System.out.println("Reading data from " + capacityGb + "GB SSD...");
    }
}

// Computer uses COMPOSITION (HAS-A Processor, HAS-A Storage)
public class Computer {
    private final Processor processor;
    private final Storage storage;

    // Components injected via constructor
    public Computer(Processor processor, Storage storage) {
        this.processor = processor;
        this.storage = storage;
    }

    public void run() {
        storage.readData();
        processor.processData();
        System.out.println("Task completed successfully.");
    }

    public static void main(String[] args) {
        Processor cpu = new Processor("Apple M2 Pro");
        Storage ssd = new Storage(512);

        // Flexible assembly via composition
        Computer myMac = new Computer(cpu, ssd);
        myMac.run();
    }
}
```
